# ShopiFow Demo 产品分析

> 基于三份需求文档的分析，聚焦客服系统和评论系统两个核心场景。

---

## 一、目标用户痛点

| 用户 | 核心痛点 |
|------|---------|
| 零售品牌（婚礼POS） | 多工具孤岛（Shopify/Klaviyo/HubSpot/Meta），数据靠人工搬运 |
| Pet Printed（9市场） | 规模化运营复杂，自动化流程要长期稳定跑，不能挂 |
| FAO 保健品（三平台） | 客服/网红/内容运营全靠人肉，低价值重复操作消耗人力 |

**三个用户的共同核心**：客服自动化 + 内容批量生成（评论回复）

---

## 二、客服系统分析

### 需求原文
> "AI-assisted or AI-first response handling across Shopify/Amazon/TikTok support channels, with clear escalation paths for edge cases."

### 真实含义拆解

**"across three channels"**
三个平台客服入口完全不同，客服团队要切换三套后台，漏单风险高，回复风格不统一。

**"AI-assisted or AI-first"**
用户未确定哪种模式，说明客服量不足以支撑全自动，但人工成本已经很高。
- AI-first：标准问题直接回复，无需人工
- AI-assisted：AI 起草，人工审核后发送

**"clear escalation paths for edge cases"**
用户曾被坑过。保健品电商的高风险场景：
- 客户反馈副作用/过敏反应 → 法律风险，AI 不能直接回
- Amazon A-to-Z claim → 回错直接影响账号健康
- 退款纠纷/差评威胁 → 需要人工判断让步策略
- 大订单/KOL 客户 → 不能用模板敷衍

### 系统逻辑设计

```
用户发消息（任一平台）
      ↓
AI 分类：标准问题？
      ├── YES（占约 70-80%）→ 自动回复
      │     - 物流查询（查订单数据）
      │     - 退换货政策
      │     - 产品 FAQ / 用法说明
      └── NO → 判断风险等级
                  ├── 低风险 → AI 起草 + 人工审核后发送
                  └── 高风险 → 立即人工接管 + 即时通知
                        - 副作用/健康投诉
                        - 平台账号威胁
                        - 大客户/KOL
```

### 三平台接入现实

| 平台 | 接入方式 | 说明 |
|------|---------|------|
| Shopify | 直接 API | 已集成，订单数据可查 |
| TikTok Shop | Gorgias 原生（2023年上线） | 无需第三方 |
| Amazon | 需要 ChannelReply（付费中间层） | Amazon 不向 helpdesk 开放直连，ChannelReply 持有官方资质 |

**ChannelReply 的作用**：监听 Amazon Buyer-Seller Messages → 转成 Gorgias ticket（附订单信息）→ 在 Gorgias 回复后转发回 Amazon。

**Zendesk vs Gorgias**：
- Gorgias：TikTok Shop 原生，Amazon 需要 ChannelReply
- Zendesk：TikTok Shop 和 Amazon 都需要 ChannelReply，不如 Gorgias

**结论**：Gorgias 更适合这个场景。真实架构：
```
Shopify     ──────────────────────────────┐
TikTok Shop ── Gorgias 原生 ──────────────┼→ Gorgias Webhook → n8n + AI
Amazon      ── ChannelReply（付费）→ Gorgias ┘
```

### Demo 实现方案

- Shopify：真实数据
- Amazon / TikTok Shop：mock 消息（带平台来源标签）
- AI 分类 + escalation 逻辑：真实运行

**演示脚本（三条消息覆盖三种路径）**：
1. "Where is my order #5678?" → AI 查订单，直接自动回复
2. "I had a bad reaction to the product" → 标记高风险，触发人工接管通知，不自动回复
3. "Can I get a refund?" → AI 起草回复，显示"等待人工确认"状态

## 三、评论系统分析

### 各平台评论 API 现实

| 平台 | 能否获取评论 | 方式 |
|------|-----------|------|
| Shopify | 能（需第三方） | Judge.me / REVIEWS.io 有 API |
| Amazon | **不能** | 官方不开放评论读取 API，爬虫违反 ToS |
| TikTok Shop | 有限 | Apify 有抓取工具，官方 API 权限受限 |

**Amazon 是死结**：行业公认，无官方 API。

### 行业实际做法

- **Judge.me**：支持从 Amazon 手动导入评论（CSV），再通过 API 统一管理
- **Bazaarvoice**：企业级，可在 TikTok Shop 和 Shopify 间同步评论，价格贵，中小品牌不适用

### Demo 实现方案

和客服系统一样，评论三平台打通不现实，Demo 用 mock 数据。

**卖点说法**：
> "Amazon 评论没有官方 API，行业通用做法是通过 Judge.me 导入或定期人工同步，AI 回复生成器接在这一层后面，不依赖平台直连。"

## 四、Demo 整体设计建议

### 核心演示流程

```
进入页面
  ↓
看板：今日已自动处理 42 个支持请求，节省 3.5 小时
  ↓
Tab 1：客服 Chat
  - 三条演示消息（自动回复 / 起草审核 / 高风险人工接管）
  - 来源标签：Shopify / Amazon / TikTok Shop
Tab 2：评论回复
  - 8条 mock 评论，一键生成品牌语气回复
  - 多语言版本生成（针对 Pet Printed 场景）
Tab 3：自动化流程
  - n8n 工作流图示
  - 触发按钮 + 实时状态更新
```

### 优先级排序

| 功能 | 开发难度 | Demo 说服力 | 优先级 |
|------|---------|------------|--------|
| 客服 AI 分类 + escalation | 中 | 高 | ★★★ |
| 评论 AI 回复生成 | 低 | 高 | ★★★ |
| 商品描述多语言生成 | 低 | 中 | ★★ |
| Automation 状态看板 | 低 | 中 | ★★ |
| TikTok 趋势 → 创意 brief | 高 | 高（针对 User 3） | ★ |

### Proposal 关键话术

1. **客服**：接入层用 Gorgias webhook，切换成 Zendesk 只需改一个 HTTP 节点
2. **Amazon**：消息通过 ChannelReply 同步进 Gorgias，其余流程与 Shopify/TikTok 一致
3. **评论**：Amazon 无官方 API，通过 Judge.me 导入，AI 回复层不依赖平台直连
4. **可靠性**：n8n 自托管，所有流程有错误处理和人工接管路径
